Product Vision

Listen Together, Anywhere

Music is inherently social. GROIC is built around a single, powerful premise: Create a room. Invite your people. Discover public rooms. Listen to music together in real time.

Whether streaming chill study beats with a friend thousands of miles away, enjoying late-night tracks with a partner in a private 2-person room, or finding community jams in public spaces, GROIC unites listeners using official YouTube embeds and Supabase Realtime synchronization.

Architecture Foundations

  • ✓ Atomic Capacity Enforcement: Secure database function (join_room_atomic) locks records with FOR UPDATE to eliminate race conditions under concurrent joins.
  • ✓ Best-Effort Drift Correction: room-sync.js calculates expected timestamp accounting for network transit, correcting drift exceeding 2.5s without infinite loops.
  • ✓ Multi-Tab Deduplicated Presence: room-presence.js tracks connected participants by user ID, avoiding artificial count inflation.
  • ✓ Pure Static Web Stack: 100% Vanilla JS, HTML5, CSS3, zero bundlers, zero npm, completely deployable to GitHub Pages.

Real-Time Social Sync & Trending Algorithms

How GROIC achieves high-accuracy shared playback and active trending rankings across distributed static clients.

🔥 Trending Rooms Score

Calculated via SQL stored procedure:

(Participants × 15) + (Recent Activities × 5) + (Occupancy% × 20) - (Hours × 0.4)

Ensures active, fresh rooms with real listeners trend above stale or empty rooms.

⏱️ Authoritative Playback State

Room rows hold:

playback_position + (now - updated_at) × playback_rate

Late joiners immediately calculate the exact millisecond offset and jump right into the audio stream.

🔒 Private Invitation Tokens

Private rooms use 8-character cryptographically random tokens:

join_room_atomic(p_room_id, p_invite_code)

Excluded from public discovery, trending rankings, and protected by PostgreSQL RLS.

Database Security & Schema

Atomic Capacity & Row Level Security (RLS)

All room capacity limits (2, 4, 6, 8, 10) are enforced in PostgreSQL transactions. You can find the full schema in supabase/schema.sql.

-- Excerpt from supabase/schema.sql: Atomic Capacity Lock
-- Lock room record to prevent race conditions during concurrent joins
select * into v_room from public.rooms where id = p_room_id for update;

-- Count current active participants
select count(*) into v_current_count from public.room_memberships
where room_id = p_room_id and status = 'active';

-- Strictly enforce configured room capacity
if v_current_count >= v_room.max_capacity then
  return jsonb_build_object('success', false, 'error', 'Room is full');
end if;
